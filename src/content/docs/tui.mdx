---
title: The TUI
description: A full-screen console for packages, sessions and members, driven by a menu and a command palette.
---

`vmono` with no arguments opens a full-screen console. A one-line bar at the top shows where you are (`packages › payments › work`) and how many packages there are; a one-line footer shows the few keys worth knowing and any notice. Between them is the list, and on a terminal 100 columns or wider a preview of the highlighted row sits beside it: a package's purpose, sessions and members, a session's branch and the live state of each member.

You rarely need a key. **`enter` opens a menu of everything you can do to the highlighted row**, with the most common action first: `Sessions` for a package, `Launch` for a session. Each entry shows its shortcut, and pressing that key from the list (or inside the menu) does the same thing, so the menu is also how you learn them. `?` lists every shortcut for the view you are on.

## Views

| View | Opened by | Shows |
| --- | --- | --- |
| packages | start | Every package: members (`2A 1R` = two active, one reference), session count, harness, clean or dirty (any session), last opened. A package from before sessions shows `migrate` |
| sessions | `→` on a package | Per session: branch, its state (clean, dirty, pushed, remote deleted, or merged and how), last opened. Merged sessions are dimmed and sorted below the rest |
| members | `m` on a session | Per member in that session: mode, branch or ref, HEAD, how far it is published, dirty and untracked counts, role |
| describe | `d` | Purpose, context, notes, sessions and members for a package; add a session's branch and live state when opened from one; location and git state for a member |
| repos | palette | Every known repo and how many packages use it; `→` lists those packages |
| harnesses | palette | Configured harnesses, whether each is on `PATH`, and the default |

`esc` goes back. `:` (or `ctrl+p`) opens the command palette, a fuzzy-filtered list of everything you can do from where you are: go to a view (`repos`, `harnesses`, `settings`, `new package`, `sessions of <package>`), any action on the highlighted row, sort the list by a column, reload, quit. `/` filters the current list as you type. Nothing refreshes by itself, except [agent state](#agent-state): `ctrl+r` reloads the current view, and a view reloads when you come back to it.

## Agent state

When sessions launch in herdr or tmux, the sessions view has an `agent` column, and the packages view counts them. Under [herdr](/docs/herdr) it says what each agent is doing (`▲ blocked`, `● working`, `○ idle`, `✓ done`); under [tmux](/docs/tmux), only that one is `running`. It is read every few seconds while one of those views is open. Updating or deleting a session whose agent is working asks for the key a second time, and so does deleting its package.

## Shortcuts

None of these are required; the menu does the same things.

| Key (packages) | Does |
| --- | --- |
| `enter` | Open the menu |
| `→` | Drill into the sessions |
| `o` / `l` | Open the most recently opened session with the default harness / pick a harness. A package with no sessions asks you to start one |
| `d` | Describe |
| `n` / `e` | New package / edit the selected one (applies to every session) |
| `i` | [Initialize the package](/docs/package-init): pick a harness to explore it and record an overview |
| `v` | Review the [commands an initialization suggested](/docs/package-init#suggested-commands) |
| `s` / `f` | Sync every session / fetch every member's source |
| `ctrl+d` | Delete the package and all its sessions (asks first; typed confirmation if work would be lost in any of them) |
| `y` | Copy the package path |
| `c` | Edit the config (package root, source roots, [hooks](/docs/setup-and-hooks#hooks)) |

| Key (sessions) | Does |
| --- | --- |
| `enter` | Open the menu: launch, launch with…, members, describe, sync, fetch, update, copy path, push, delete |
| `o` | Launch the default harness in the session |
| `l` | Pick a harness |
| `n` | [Start a new session](/docs/starting-a-session#from-the-tui): a name, and optionally a prefix, a branch, a remote branch to work on (`track`, or `ctrl+t`) or to build on (`from`), and a branch per active member |
| `P` | [Push](/docs/pushing-a-session#from-the-tui) the session: shows where each member's branch goes, what is uncommitted and left out, or what blocks it, then `y` pushes. Never forced |
| `m` / `d` | Members of the session / describe it |
| `u` | [Update](/docs/updating-a-session) the session: rebase branches that are not pushed, and merge what is new into those that are |
| `s` / `f` | Sync the session / fetch every member's source |
| `e` | Edit the package |
| `ctrl+d` | [Delete](/docs/after-merging#removing-a-session) the session; the package and its other sessions stay. Shows what becomes of each branch; `b` also deletes the merged ones |
| `y` | Copy the session path |

| Key (members) | Does |
| --- | --- |
| `p` | Push the highlighted member's branch (same dialog as `P`, for one member) |
| `P` | Push every member of the session |

Members, repos and harnesses have menus too (`enter`), with the same keys where they apply. The members preview shows what each branch is built on, its commits, and how far it is published or how it merged; a session's preview sums what is left to push. Sorting is only in the palette (`sort by name`, `sort by opened`, …); choosing the same column again reverses it.

Launching starts the harness where the `launcher` setting says. With the [tmux integration](/docs/tmux), a launch switches your tmux client to the session's own tmux session, and a TUI opened from the `prefix + V` popup closes once it has. With [herdr](/docs/herdr), a launch goes to the session's workspace, and a TUI opened from the `prefix + shift + v` popup closes. If tmux or herdr fails, the TUI stays open and shows its message.

Creating a package returns to the packages screen; start a session from there (`enter`, then `New session`, or `→` then `n`) when you want one.

## The repo finder

Repos that are not under a source root, or every repo when no source root is set, are found with the repo finder (`p` while choosing members, `a` in the repos view). Type a path and it lists the directories there, marks the git repos (`●`), and scans below a typed directory for repos nested deeper. `tab` completes, `enter` picks a repo or steps into a directory; picked repos are remembered.
