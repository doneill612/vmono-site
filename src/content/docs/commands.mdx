---
title: Commands
description: Every vmono command, its flags, and its exit codes.
---

Every read command takes `--json`. Anything that could discard work refuses unless given `--force`. Any command takes `--no-hooks` to skip [hooks, setup and teardown](/docs/setup-and-hooks). Inside a session, the package and session arguments are optional. Commands that act on a session take `pkg/session`; a bare `pkg` works when it has exactly one session, and otherwise the error lists them.

| Command | Does |
| --- | --- |
| `vmono` | Open the TUI |
| `vmono init [--source-root P]... [--package-root P]` | Write the global config without prompts |
| `vmono ls` / `vmono repos` | List packages / known repos |
| `vmono new <pkg> --active a,b [--ref c] [--purpose-file F] [--context-file F] [--harness H] [--session S [--prefix P] [--branch [MEMBER=]B]... [--track [MEMBER=]B]... [--from [MEMBER=]REF]... [--reuse-branch]]` | Define a package, and optionally start its first session |
| `vmono session new [pkg] <name> [--prefix P] [--branch [MEMBER=]B]... [--track [MEMBER=]B]... [--from [MEMBER=]REF]... [--reuse-branch]` | Start a session: a worktree of every member, each active one on a branch. See [Starting a session](/docs/starting-a-session) |
| `vmono session ls [pkg]` | List a package's sessions and whether each is in progress, pushed or merged |
| `vmono session update [pkg/session] [--member NAME]... [--no-fetch] [--dry-run] [--json]` | Fetch, then rebase each branch that is not pushed onto its base, and merge what is new into each that is. See [Updating a session](/docs/updating-a-session) |
| `vmono session review [pkg/session] [--member NAME]... [--json]` | Show what a push would publish, changing nothing (the read-only form of `session push`) |
| `vmono session push [pkg/session] [--member NAME]... [--dry-run] [--json]` | Push each member's branch to its remote, never forced. See [Pushing a session](/docs/pushing-a-session) |
| `vmono session rm <pkg>/<session> [--force] [--delete-branches]` | Remove a session; the package and its other sessions stay. Branches are kept unless empty, or merged and asked for. See [Removing a session](/docs/after-merging#removing-a-session) |
| `vmono package init [pkg] [--harness H]` | Explore the members with a harness and record an overview. See [Initializing a package](/docs/package-init). `--clean [--force]` removes a checkout an earlier run left behind |
| `vmono package record [pkg] (FILE \| -)` | What the agent records with: JSON with `overview`, and optionally `purpose`, `roles` and `suggestions` |
| `vmono package suggestions [pkg]` | List the setup and teardown commands an agent suggested. `--review` goes through them; `--accept ID,...` and `--dismiss ID,...` settle them; `--json` |
| `vmono add [pkg] <repo> [--ref] [--role R]` | Add a member to the package, and so to every session (a known repo name or any path) |
| `vmono rm [pkg] <member> [--force] [--delete-branch]` | Remove a member from every session. `--delete-branch` also deletes its merged branches |
| `vmono edit [pkg] [--force] [--reuse-branch]` | Edit the package manifest in `$EDITOR`; changes apply as a diff to every session. `--force` allows removals that discard unsaved work; `--reuse-branch` checks out a session branch that already exists |
| `vmono sync [pkg[/session]] [--refs]` | Recreate missing worktrees and regenerate files, in one session or all of a package's; `--refs` moves reference members to their latest fetched ref |
| `vmono status [pkg[/session]]` | The session's state, and per member: branch or ref, uncommitted work, and how far it is from pushed and merged |
| `vmono show [pkg[/session]]` | Purpose, context, notes, sessions and members; with a session, each member's live state |
| `vmono describe [pkg] --purpose T \| --context T \| --overview T` | Replace the purpose, context or overview (`--purpose-file`, `--context-file`, `--overview-file` too) |
| `vmono role [pkg] <member> TEXT` | Set a member's role |
| `vmono note [pkg] TEXT` | Append a note to the package, stamped with time and author |
| `vmono open [pkg[/session]] [--harness H] [-- ARGS]` | Launch a harness at a session root, in this terminal or in a tmux session or herdr workspace of its own, as the `launcher` setting says |
| `vmono path [pkg[/session]]` | Print a session's path, or the package's when no session is meant |
| `vmono delete <pkg> [--force] [--delete-branches]` | Tear down a package and every one of its sessions |
| `vmono inspect [pkg[/session]]` | A session's full resolved model as JSON, including each member's `git_common_dir` |
| `vmono doctor [--fix]` | Find drift, migrate packages and sessions from [earlier versions](/docs/after-merging#upgrading-from-earlier-versions), and rebuild the index |
| `vmono shell-init zsh\|bash\|fish\|pwsh` | Print a `vcd <pkg>[/session]` function |
| `vmono integration ls [--json]` | List integrations and whether each is installed |
| `vmono integration install <name> [--no-launcher] [--key K]` | Write an integration's files, wire them into the tool, and turn on its launcher. `--key` picks the key that opens the TUI (herdr). See [tmux](/docs/tmux) and [herdr](/docs/herdr) |
| `vmono integration uninstall <name>` | Remove what install added |
| `vmono integration print <name>` | Print an integration's files instead of installing them |

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success |
| `1` | Error |
| `2` | Refused because work would be lost; or, for `session push` and `review`, because a member is blocked; or, for `session update`, because a member was skipped or conflicted; or because a `pre_remove` hook set to abort kept the session |
| `3` | Not found, including a `--track` or `--from` for something that the named member, or every member, lacks |

When a harness started with `vmono open` exits, vmono exits with its status.
