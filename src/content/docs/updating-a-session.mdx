---
title: Updating a session
description: Bring each branch up to date with its base, by rebasing until it is pushed and merging afterward.
---

`vmono session update [pkg/session]`, or `u` on the session in the TUI, fetches the sources and takes in what is new. How each active member is updated depends on whether its branch has been pushed. Your local branches are never moved, and are read only where something is built on one: a base given as a plain name, or a session built on a [local branch](/docs/starting-a-session#what-a-new-branch-starts-from).

## What happens to each branch

| Branch | What update does |
| --- | --- |
| Not pushed | Rebases your commits onto the base. Nobody else has them |
| Pushed | Merges its remote copy and then the base, fast-forwarding where it can, so pushing again never needs force |
| Built on another branch with `--from` | Follows that branch, local or remote as chosen; once it has merged, moves to the base, leaving its commits behind. A local branch that is only behind its remote copy does not count as merged |
| Already merged | Leaves it alone; see [Merging and cleanup](/docs/after-merging) |
| Remote branch deleted | Skips it |
| Its history, or the remote copy's, was rewritten | Skips it: merging would bring the old commits back |

Updating never rewrites commits that have been pushed.

## Members are independent

One with uncommitted changes is skipped when there is something to take in. So is one whose worktree is missing, on another branch, or in the middle of a rebase, each with the reason.

A rebase or merge that conflicts is aborted, so that member stays exactly as it was, and the reason names the files and the commands to resolve it. Run them in the member's worktree, then update again. In the TUI, a failed update offers to launch the harness in the session to resolve it.

## Flags and exit code

| Flag | Does |
| --- | --- |
| `--member NAME` | Update only this member (repeatable) |
| `--no-fetch` | Use the refs already on disk. A fetch that fails only warns |
| `--dry-run` | Fetch, then show what would be updated without moving any branch |
| `--json` | Print the result per member |

The command exits `2` when any member was skipped or conflicted.

## While an agent is working

An update can rewrite or add to a branch, so do it while no agent is in the middle of a change. In the TUI, updating a session whose agent is working asks for `u` a second time. If you never run it, conflicts with the base just show up on the pull request.

The vmono skill teaches the agent to run an update when you ask for one, or when a push is blocked because a branch diverged. Where history was rewritten, it explains and asks you first; it never resets or force-pushes on its own.
